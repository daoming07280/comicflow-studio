# Edge 配音中断修复

## 实际问题

任务 `ab5eca50f29e`（赫尔穆特）共 610 段，在第 176 段出现 `NoAudioReceived`，连续三次没有音频后停止。日志没有 HTTP 429，不能把这一次失败直接认定为限流。

复现发现：云希、+10% 语速下，「外面的人类。」会无音频；去除句末句号，或把整段句号调整为逗号后，可以合成。其他测试文本在同一环境下正常。这表明除临时网络/服务限制以外，还存在特定文本与标点组合的服务兼容问题。

## 修复

- 所有 Edge 配音和试听共用线程锁与进程锁；请求完成后至少间隔 5 秒，避免同时请求。
- 不再连续立即请求三次。首次 NoAudioReceived 且能调整标点时，按正常 5 秒间隔做一次兼容重试；其他失败按 15、30、60、120、240 秒退避，最多 6 次，响应含 Retry-After 时尊重服务要求的等待时间。
- 工作台显示冷却倒计时，等待和网络请求均可停止；不会吞掉停止信号。
- 遇到 NoAudioReceived 后，依次调整中文句号为逗号、去除中文句号，再按原标点拆成短句单独合成；保持全部字词和所选音色。拆分后仍经过同一限速器，原文案与字幕保持原样。
- 长文本按最多 160 字符切分并逐段缓存；已完成片段校验通过后复用。
- 新音频需收到覆盖全部可朗读字词的文本边界，完整解码，并确认音频覆盖最后一个边界的结束时刻。只有完成这些检查才发布缓存；未完成的临时音频被清理。
- 已有音频先做解码检查再保留；若文件破损则重新生成。旧缓存没有语音边界信息，因此这一步只能证明其技术完整性，不能追溯证明每个旧字词都被朗读。
- 连续失败时保留断点，明确显示重试结果，不输出缺少后半段的“成功”成片。不自动切换声音，避免一部合集前后音色变化。

限速与重试能提高稳定性，但不能保证第三方服务永远可用。Edge 长期不可用时，工作台仍可选 Windows 离线配音；整项任务切换引擎会改变声音，需要作为独立制作选择。
